### ✅ Day 8 최종 체크포인트

Q1. 본인의 프로젝트에서 Pydantic 검증은 어떤 잘못된 입력을 막아줍니까?

- min_length=1과 max_length=5000 조건을 지정하여 만약 문장이 1글자 미만이거나 5000자 이상이면 입력을 막는다
- 또한 텍스트가 없이 공백만이 전달될 경우 공백 입력을 막는 검증이 수행된다.

Q2. Depends(verify_api_key)를 제거하면 어떤 위험이 있습니까?

- API Key 인증 절차가 없이 누구나 해당 API를 사용할 수 있게 된다.
- 이번 프로젝트의 경우 텍스트를 수초안에 수백, 수천개씩 보내서 서버를 다운시키는 등 텍스트 입력과 전송을 이용한 서버 다운 시도에 노출될 수 있다.

Q3. run_in_executor를 사용한 이유는 무엇입니까?

- 모델 추론과 같이 CPU를 대기시간 없이 계속 사용해야 하는 동기 연산 작업을 비동기 연산과 함께 수행할 경우, 동기 연산이 수행되는 동안은 다른 작업이 모두 대기를 하게 된다. 따라서 기존 스레드의 비동기 연산의 효과를 살리면서 동기 연산 작업도 함께 할 수 있도록 run_in_executor를 사용하여 동기 연산을 별도의 스레드에서 수행할 수 있게 한다.

Q4. Day 1~8 중 가장 많이 참고한 Day는 어디였습니까? 왜?

- 가장 많이 참고한 Day는 PyTorch로 직접 만든 모델이 아닌, 오픈 소스 모델을 가져와서 작업을 했던 Day7이었다. Day7도 오늘 프로젝트와 동일하게 Hugging Face transformers 라이브러리를 활용하였기 때문에 개념을 다시 찾아볼때 도움이 되었다. 그 외에도 기존에 만들어놨던 py 파일들을 참고하였다.

Q5. 이 서비스를 실제로 배포하려면 추가로 무엇이 필요합니까?

- 현재 서버는 localhost 주소를 쓰고 있다. 따라서 실제로 배포하기 위해서는 다른 사용자들도 사용할 수 있도록 서버를 공개하는 과정이 필요하다. 또한 단순히 서버를 공개하는 것을 넘어, 안정적으로 서비스 하기 위해서는 AWS, GCP 등의 클라우드 서버 호스팅이 필요하다. 또한 Docker를 이용한 환경 컨테이너화, Nginx 같은 리버스 프록시 적용 및 HTTPS(SSL) 보안 설정, 트래픽을 감당하기 위한 Gunicorn+Uvicorn 다중 워커 구성 등이 추가로 필요하다.

## ✍️ 프로젝트 회고

오늘 프로젝트는 최종적으로 “감성 분석”이라는 도메인을 선택하여 text-classification 태스크를 수행하였습니다. 한글 문장의 감성 분석을 수행하기 위해서 모델은 snunlp/KR-FinBert-SC를 사용하였습니다. 모델의 크기가 406MB로 CPU에서 작업을 수행하기에 무리가 없는 모델이었습니다.

이 모델을 최종 선정하기까지 몇 번의 시행착오가 있었습니다. 첫 번째로, 수영을 하는 사람이 나오는 사진 또는 영상을 통해 팔과 다리 관절을 인식하는 인체 자세 추정(키포인트 검출) 사전 학습 모델을 시도했습니다. 선택했던 모델은 ViTPose 컬렉션의 ViTPose-Plus-Base로, 비전 트랜스포머(ViT) 백본을 사용하여 관절 추정 정확도가 높은 모델이었습니다. 다만 이 모델은 `pipeline()`을 사용할 수 없고 `from_pretrained()`를 사용하여 모델을 테스트 구동하는 과정에서 오류가 발생하여, 정해진 시간 안에 프로젝트를 완료하기에는 무리가 있을 것으로 판단해 보류하였습니다.

두 번째로 시도한 모델은 YOLO11-pose를 기반으로 측면(side-view) 촬영 이미지 28,000건을 파인튜닝한, 수영하는 사람의 자세 감지 및 추적에 특화된 `KadyT/Swimmer` 모델이었습니다. transformers 라이브러리에 포함되어 있지는 않지만 ultralytics를 활용하여 간단하게 구동할 수 있었습니다. 하지만 테스트 결과를 확인해 보니 감지 능력이 현저하게 낮아 모델 선정에서 제외하였습니다.

세 번째는 Hugging Face transformers를 사용할 수 있는 사전 학습 모델 `eenzeenee/t5-base-korean-summarization`을 활용하고자 하였습니다. 한글 문장을 전달하면 요약문을 출력하는 모델이었으나, `pipeline('summarization')`이 정상적으로 구동하지 않는 문제가 발생하여 이 모델 역시 제외하였습니다.

프로젝트 구현 과정에서는 미리 제시된 수행 순서에 맞춰 작업을 진행하였기 때문에 개념적으로 크게 어려운 부분은 없었습니다. 다만 구체적인 코드를 작성할 때 기억나지 않는 문법들이 종종 있어서 앞서 작성했던 코드들을 찾아보며 오늘 태스크에 맞게 수정하는 과정을 거쳤습니다. 특히 `schema_pj2.py`와 `main_pj2.py`, 그리고 `app_pj2.py`를 작성할 때는 기존에 실습했던 코드들을 많이 활용했습니다.
